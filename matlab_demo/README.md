# Демо: токовая диагностика двигателя + нейроморфная платформа «Алтай» (KNP)

## Как запустить
1. Запустить **Docker Desktop**. Нужен для секций 10–13 (контейнер `knp-lab` — «Алтай» v1.0.0, `knp-run` — KNP v2).
2. Если контейнеры остановлены (например, после перезагрузки Mac), выполнить в терминале:
   `docker start knp-run knp-lab`. Если их ещё нет — собрать: `bash knp-lab/setup_docker.sh` (из корня репозитория).
   Файлы `../data/mat/*.mat` создаёт `python analysis/make_mat.py` (см. корневой README).
3. В MATLAB открыть `start_here.m` и запускать по секциям (Cmd+Enter) или всё сразу (Run).
   Номер испытания для просмотра задаётся переменной `TRIAL` в начале скрипта (1–45).

## Синтетические дефекты и «Алтай» (`../analysis/synth/`)
1. `common.py` — физика: дефект = модуляция тока на своей частоте (BPFO, BPFI, 2·BSF, FTF, 1× и 2× вала).
2. `gen_features.py` — 8550 примеров (куски по 10 с × {норма + 6 дефектов × 3 степени}) → 7 признаков.
   **Рабочая полоса 0–150 Гц**: ток фильтруется и прореживается до 512 Гц, частоты выше 150 Гц не используются.
3. `train_ternary.py` — обучение сети под ограничения чипа: 42 бинарных входа → 9 нейронов AltAILIF,
   веса только −1/0/+1 (60 синапсов). Обучение на записях 1–30, проверка на 31–45.
4. `gen_blind.py` — 45 «слепых» CSV в формате преподавателя (`../data/synthetic/csv`) + ключ `labels.csv`.
5. `chip_eval.py`, `infer_blind.py`, `diagnose_file.py` — запуск сети на «Алтае» через Docker,
   сверка бит-в-бит с эталоном, диагноз по файлу.

Результат на «Алтае» v1.0.0 (полоса 0–150 Гц): 45 файлов — тип верно 34/45 (76%): норма 9/9, сильные 12/12,
средние 11/12, слабые 2/12; степень верно 82%. Все ошибки — пропуски слабых дефектов, путаницы типов нет.
Все спайки совпали с эталоном бит-в-бит (2964/2964 и 270/270).

## Спектр огибающей и вейвлеты (`../analysis/`)
- `envelope.py` — огибающая несущей (1 фаза, вектор Парка), огибающая ВЧ (фиксированная полоса, STFT-кюртограмма,
  выбор полосы по частотам дефекта). Прогон по 45 записям → `envelope.csv`.
- `wavelet.py` — скалограмма CWT, вейвлет-пакетная кюртограмма и выбор узла по частотам дефекта, вейвлет-шумоподавление,
  стационарность записей. Прогон → `wavelet.csv`.
- `synth/common.py: inject_impacts()` — ударная модель дефекта подшипника (импульсы с проскальзыванием на резонансе 2–6 кГц).
- `compare_methods.py` — проверка всех методов на синтетике поверх реальных записей → `compare_methods.csv`.
- `plot_methods.py` — рисунки `figures/m_*.png`.

## Главные выводы на сейчас
- Частота питания 48,5 Гц, двигатель питается от ПЧ (ШИМ 3 кГц). Реальная скорость ~1452 об/мин.
- 45 испытаний = 6 режимов работы. Внутри одного режима записи стандартными признаками токовой диагностики неразличимы.
- Разметки в данных нет. Вероятный первоисточник — открытый датасет KAIST (Mendeley, ztmf3m7h5x): тот же стенд, 15 состояний × 3 нагрузки = 45, с метками дефектов. Его можно использовать для проверки результатов.
- Эмулятор «Алтай» в текущем релизе не загружает сети. Нейроморфная часть показана на KNP (CPU) с тем же API.
